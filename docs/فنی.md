# مستندات فنی سوزان

این فایل مرجع فنی کل پروژه است. قرارداد معماری، پشته، لایه‌ها، API، استقرار، امنیت و محدودیت‌ها اینجاست. روایت محصول برای فروشنده در `docs/کارهای-سوزان.md` است.

---

## محصول

سوزان پنل ساخت و ادارهٔ فروشگاه اینترنتی است. فروشنده با شماره وارد می‌شود، در چت فروشگاه سایت را سفارش می‌دهد، در استودیو محتوا می‌سازد، از صندوق به مشتری جواب می‌دهد، و فروش و کیف را از پنل می‌بیند.

جملهٔ محصول: **بگو، بساز، بفروش.**

برند: علامت خورشید و ماه مسی روی پلاک زغالی. UI پنل فارسی و RTL است؛ فونت نمایش Estedad و خانوادهٔ Vazirmatn در دارایی‌های برند است.

| نقش | نشانی |
| --- | --- |
| معرفی | https://sozan-core.ir |
| پنل | https://app.sozan-core.ir |
| API | https://api.sozan-core.ir |
| فروشگاه | `https://{slug}.sozan-core.ir` بعد از ساخت |

بازدیدکننده HTTPS می‌گیرد. لبهٔ ابرآروان با سرور اصلی **HTTP** حرف می‌زند.

---

## پشتهٔ قفل‌شده

خارج از این فهرست چارچوب جدید اضافه نشود.

**بک‌اند**

- FastAPI
- SQLAlchemy Async + asyncpg
- PostgreSQL 16
- Redis 7
- Pydantic Settings، PyJWT، httpx، Pillow

**فرانت**

- Next.js 15 (App Router) + React 19
- TypeScript
- Tailwind CSS
- shadcn/ui (دکمه‌ها، اینپوت، کارت، سلکت، تکست‌اریا)

**قرارداد امنیتی بک‌اند**

- ورود با OTP؛ کد در Redis با TTL
- نشست با JWT (`HS256`)
- بررسی دسترسی روی هر اندپوینت محافظت‌شده
- رازها فقط در `.env` با مجوز محدود؛ هرگز در گیت

## معماری تمیز

لایه‌ها از بیرون به درون:

```
مسیر HTTP (api/)
    → سرویس (services/)
        → مخزن (repositories/) → Postgres
        → state_store → فایل JSON هر مستأجر
        → redis_client → OTP و محدودیت نرخ
```

قواعد:

1. مسیر (`backend/app/api/`) فقط اعتبارسنجی ورودی، وابستگی‌ها و تبدیل خطا است. به دیتابیس دست نمی‌زند.
2. منطق کسب‌وکار فقط در `services/` است.
3. تنها `repositories/` به SQLAlchemy/Postgres دسترسی دارد.
4. وضعیت فروشنده (فروشگاه، کیف، صندوق، کانال، کاتالوگ، …) روی دیسک است، جدا از جدول‌های Postgres.
5. فرانت فقط از طریق API حرف می‌زند؛ کلاینت در `frontend/lib/api.ts` است.

### Postgres چه چیزی نگه می‌دارد

جدول‌های SQLAlchemy در `backend/app/models/user.py`:

| جدول | نقش |
| --- | --- |
| `users` | حساب با شمارهٔ ۱۱رقمی، نقش، فعال بودن |
| `campaigns` | کمپین استودیو (slug، ستون، تیتر) |
| `assets` | فایل خروجی کمپین |
| `copy_variants` | کپشن هر کانال |

بقیهٔ دامنه (فروشگاه، انبار، فروش، کیف، پلن، صندوق، کانال، تنظیمات) JSON داخل `backend/data/tenants/{phone}/` است. این پوشه در گیت نیست.

### Redis چه چیزی نگه می‌دارد

- `otp:{phone}` — کد ورود با TTL (پیش‌فرض ۳۰۰ ثانیه)
- `otp:rl:{phone}` — محدودیت نرخ ارسال OTP (حداکثر ۵ در ۹۰۰ ثانیه)

## چندمستأجری

هر فروشنده با شمارهٔ نرمال‌شده یک پوشه دارد: `backend/data/tenants/{phone}/`.

`state_store.set_tenant` از JWT بعد از ورود ست می‌شود. حلقه‌های پس‌زمینه با `tenant_scope(phone)` روی همهٔ مستأجرها می‌گردند.

نمونه‌های فایل هر مستأجر: `shop.json`، `products.json`، `inbox.json`، `wallet.json`، `plan.json`، `channels.json`، `shop-workspace/` (دستورهای چت و فایل ادیت).

فایل‌های مشترک (نه per-tenant): `profiles.json`، `settings.json`، `llm-routing.json`.

## معماری استقرار

پنل، API، Postgres، Redis و پراکسی فروشگاه‌ها روی **هاب** هستند. گیت‌وی OpenClaw و وزن مدل روی **ماشین خانه** می‌مانند.

```
بازدیدکننده --HTTPS--> ابرآروان --HTTP :8088--> nginx هاب
                              |-> پنل 127.0.0.1:3010
                              |-> API 127.0.0.1:8012
                              '-> فروشگاه 127.0.0.1:{port}

API هاب --18789--> گیت‌وی سوزان روی 94.183.65.149
اینستاگرام/تلگرام از SOCKS خانه 127.0.0.1:10888
مدل از تونل معکوس SSH روی 127.0.0.1:9292
```

- IP عمومی هاب برای مبدأ CDN: `37.152.189.216`
- IP خانه برای گیت‌وی: `94.183.65.149`
- origin بین لبه و هاب HTTP است؛ TLS مال لبه است.

### پورت‌های هاب

این فرایندها روی لپ‌تاپ توسعه شبیه‌سازی کامل نمی‌شوند.

| پورت | bind | سرویس |
| --- | --- | --- |
| ۸۰ / ۴۴۳ | همه | nginx موجود هاب؛ سوزان آن را نمی‌دزدد |
| ۸۰۸۸ | همه | origin سوزان برای ابرآروان (HTTP) |
| ۳۰۱۰ | 127.0.0.1 | پنل Next (`sozan-panel.service`) |
| ۸۰۱۲ | 127.0.0.1 | FastAPI (`sozan-api.service`) |
| ۱۵۴۳۲ | 127.0.0.1 | Postgres سوزان (docker) |
| ۱۶۳۷۹ | 127.0.0.1 | Redis سوزان (docker) |
| ۱۲۴۱۰+ | 127.0.0.1 | کانتینر فروشگاه وقتی کارخانه روی هاب باشد |
| ۱۰۸۸۸ | 127.0.0.1 | SOCKS کانال‌ها از تونل خانه |
| ۱۰۸۸۹ | 127.0.0.1 | پروکسی npm از تونل خانه |
| ۱۰۸۹۰ | 127.0.0.1 | SOCKS یونى‌پایل (`sozan-unipile-socks.service`) |

سوزان از پورت‌های اشغال‌شدهٔ دیگران استفاده نمی‌کند: `8000`، `8080`، `8090`، `5432`، `6379`، `3001`.

توسعهٔ محلی: `docker-compose.yml` ریشه Postgres را روی `5432` و Redis را روی `6379` می‌آورد. پنل `next dev` روی `3000` است و API پیش‌فرض فرانت `http://127.0.0.1:8000` است مگر `NEXT_PUBLIC_API_URL` ست شود. روی دامنهٔ زنده، فرانت همیشه به `https://api.sozan-core.ir` می‌رود.

### پورت‌های خانه — فوروارد به `94.183.65.149`

| پورت | وضعیت | کاربرد |
| --- | --- | --- |
| ۱۸۷۸۹ | باز از هاب | گیت‌وی OpenClaw سوزان |
| ۱۹۰۰۱ | اگر بالا باشد | Final Core |
| ۱۹۰۰۲ | اگر بالا باشد | Final VPN |
| ۱۹۰۰۳ | اگر بالا باشد | Final Cyber |
| ۹۲۹۲ | فقط localhost | مدل؛ با `ssh -R` به هاب می‌آید نه با فوروارد WAN |

فوروارد نشود: `5432`، `6379`، `8000`، `3000`، پورت‌های `12xxx` فروشگاه.

واحد systemd کاربر روی خانه: `llama-swap.service` (`19292`)، `sozan-observe.service` (`9292`)، `sozan-llm-tunnel.service`. llama-swap و observe روی `0.0.0.0` باز نشوند.

مانیتور اپراتور فقط روی خانه: `http://127.0.0.1:9292/observe/`. خروجی فاین‌تیون `/observe/api/export.jsonl` به گیت یا هاب کپی نشود.

## احراز هویت و مجوز

1. `POST /auth/otp/send` شماره را نرمال می‌کند، کد ۶رقمی می‌سازد، در Redis می‌گذارد، در تولید با SMS.ir می‌فرستد.
2. اگر `OTP_DEV=true` یا `mockSms` در تنظیمات روشن باشد، کد در JSON با کلید `dev_code` برمی‌گردد.
3. `POST /auth/otp/verify` کد را می‌سنجد، کاربر را می‌سازد یا پیدا می‌کند، JWT می‌دهد.
4. فرانت توکن را در `localStorage` با کلید `sozan_token` نگه می‌دارد و روی هر درخواست `Authorization: Bearer` می‌گذارد.
5. `get_current_user` توکن را باز می‌کند، کاربر فعال را از Postgres می‌خواند، tenant را ست می‌کند.
6. بیشتر مسیرهای پنل `require_permission("campaigns:read"| "campaigns:write")` دارند. نقش پیش‌فرض کاربر `admin` است و این دو مجوز را دارد.
7. عملیات مدیر هاب (برداشت کیف) علاوه بر مجوز، شماره را با `ADMIN_PHONE` می‌سنجد.

OTP فروشگاه برای چک‌اوت مشتری جداست: `POST /p/otp/send` و `/p/otp/verify`.

## کارخانهٔ فروشگاه

درخت slim کارخانه روی هاب: `/home/ubuntu/site-builder` (بدون `builds/` سنگین). اسکریپت: `tools/sozan_factory_fastpath.py`.

جریان:

1. چت حس، رنگ و امکانات را جمع می‌کند. «بساز» کارخانه را با گیت‌وی خانه و مدل تونل‌شده اجرا می‌کند.
2. اسکن اینستاگرام/تلگرام از کپشن عمومی کاتالوگ واقعی می‌سازد. کالای قالب مد ساخته نمی‌شود.
3. تصویر ژنراتوری روی هاب به‌عنوان مسیر اصلی ساخته نمی‌شود (`--skip-images`). عکس پست کانال روی کارت کالا می‌رود. اگر اسکن عکس نداشته باشد، قبل از بیلد از observe (`/observe/api/image`) عکس کالا/هیرو گرفته می‌شود.
4. نوع سایت از دستهٔ کاتالوگ می‌آید نه `fashion` ثابت.
5. دستورهای فروشنده در `shop-workspace` همان مستأجر می‌ماند (`commands.jsonl`، `instructions.md`، `files/`).
6. npm فروشگاه از `registry.npmjs.org` با تونل HTTP خانه (`127.0.0.1:10889`) نصب می‌شود.
7. کانتینر فروشگاه به `127.0.0.1` بایند می‌شود. nginx با `deploy/shop-upstreams.map` Host را به پورت همان فروشگاه می‌فرستد.
8. پیش‌نمایش زنده داخل چت است (مقیاس ۷۵٪، حالت طراحی). ادیت متن/رنگ همان لحظه دیده می‌شود؛ کارخانه تا دکمهٔ بیلد یا «دوباره بساز» راه نمی‌افتد.

اگر اسکریپت کارخانه نباشد، چت خطای «اسکریپت کارخانه پیدا نشد» می‌دهد.

چت استودیو مدل تونل‌شده را می‌زند و کمپین را در Postgres ذخیره می‌کند. ساخت ویدیو به `ffmpeg` روی هاب نیاز دارد؛ بدون ffmpeg کپشن ذخیره می‌شود و علت در همان جواب می‌آید.

`promo-engine/` موتور جدا برای تبلیغ خود برند سوزان است (ستون‌های shop / gateway / panel). به API پنل وابسته نیست. خروجی‌اش در `promo-engine/output/` است و در گیت نیست.

## کانال‌ها و صندوق

در ثبت‌نام فقط یک کانال خواندنی (اینستاگرام یا تلگرام) کافی است. ورود پیام و ارسال پست از بیشتر → کانال‌هاست.

| کانال | خواندن ویترین | صندوق | پست استودیو |
| --- | --- | --- | --- |
| اینستاگرام | اسکن عمومی بدون توکن؛ اتصال رسمی Sendbox | وب‌هوک Sendbox | Content Publishing با URL HTTPS امضاشده |
| تلگرام | اسکن عمومی | `getUpdates` / `sendMessage` | `sendPhoto` / `sendVideo` به مقصدی که بات ادمین است |
| واتساپ | فید عمومی ندارد | Cloud API | پیام به `postTarget`؛ خارج از ۲۴ ساعت معمولاً قالب تأییدشده |

Sendbox مسیر اصلی اینستاگرام است (`SENDBOX_API_KEY`، `SENDBOX_OAUTH_URL`). یونى‌پایل فقط اگر Sendbox خاموش باشد همان دکمه را می‌گیرد. توکن دستی برای اپراتور هنوز کار می‌کند.

پاسخ صندوق فقط وقتی در پنل ثبت می‌شود که ارسال به کانال موفق باشد. بات تلگرام روی پلن رایگان هم کار می‌کند. خواندن دایرکت اینستاگرام روی پرو و پرو مکس است.

حلقهٔ `channel_poll_service.poll_all` هر ۴ ثانیه در lifespan API اجرا می‌شود. خانه‌تکانی هر ۶۰ ثانیه کمپین و ارسال‌های کهنه را پاک می‌کند.

## پرداخت، کیف، پیامک، پلن

- اگر فروشنده مرچنت شخصی زرین‌پال یا آیدی‌پی داشته باشد، پول در حساب خودش می‌نشیند؛ سوزان کمیسیون نمی‌گیرد.
- وگرنه درگاه سوزان است؛ `COMMISSION_BPS` پیش‌فرض ۲۰۰ یعنی ۲٪؛ ۹۸٪ قابل‌برداشت است.
- برداشت با شبا؛ فقط `ADMIN_PHONE` تأیید یا رد می‌کند.
- اشتراک پرو / پرو مکس با زرین‌پال هاب؛ اگر ماندهٔ کیف کافی باشد از کیف کم می‌شود.
- فروش دستی وارد کیف نمی‌شود.
- OTP پنل و OTP مشتری فروشگاه از SMS.ir هاب می‌رود.
- سقف پیامک ماه: رایگان ۵۰، پرو ۵۰۰، پرو مکس ۲۰۰۰؛ اضافه از کیف.

| پلن | سایت | کانال | صندوق | پیامک ماه |
| --- | --- | --- | --- | --- |
| رایگان | ۱ | ۲ | جواب دستی؛ تلگرام کار می‌کند | ۵۰ |
| پرو | ۳ | ۵ | دایرکت + پیش‌نویس | ۵۰۰ |
| پرو مکس | نامحدود | نامحدود | پاسخ خودکار با لحن فروشنده | ۲۰۰۰ |

## مدل زبانی

چت پنل از `LOCAL_LLM_URL` روی هاب می‌رود؛ پیش‌فرض `http://127.0.0.1:9292/v1` از تونل به sozan-observe روی خانه، و از آنجا به llama-swap روی `127.0.0.1:19292`.

پیش‌فرض‌های `.env.example`:

- چت: `CHAT_LLM_MODEL` (مثلاً `ornith-1.5-35b`)
- استودیو: `STUDIO_LLM_MODEL` (مثلاً `qwen3.5-9b`)
- مدل محلی پایه: `LOCAL_LLM_MODEL` (مثلاً `qwen3.8-27b`)

`llm_routing_service` مسیر مدل را برای سطح‌های `shop`، `shop-edit`، `studio`، `inbox`، `voice`، `factory`، `image` از observe می‌گیرد و در `llm-routing.json` می‌نویسد. اگر تونل ۹۲۹۲ قطع شود چت مدل خطا می‌دهد تا تونل برگردد.

گیت‌وی عمومی در تنظیمات: `GATEWAY_SOZAN_URL` مثلاً `http://94.183.65.149:18789`.

## DNS و دامنهٔ شخصی

زون `sozan-core.ir` در ابرآروان است. رکورد A ابری با `upstream_https=http` برای `@`، `www`، `app`، `api` و بعد از ساخت برای `{slug}`. ویلدکارد `*` از API ابرآروان برای این زون ساخته نشد؛ هر فروشگاه رکورد جدا می‌گیرد.

دامنهٔ مشتری: پنل CNAME به `{slug}.sozan-core.ir.` نشان می‌دهد. سوزان DNS رجیسترار مشتری را عوض نمی‌کند. بعد از ذخیره، lookup وضعیت را نشان می‌دهد و دامنه با CNAME Setup ابرآروان ثبت می‌شود تا SSL لبه برای هاست سفارشی صادر شود. nginx همان Host را به پورت همان فروشگاه می‌فرستد (`deploy/shop-custom-names.conf`).

کلید API ابرآروان فقط در env هاب با mode `600` است.
