## محصول و نشانی

سوزان پنل ساخت و ادارهٔ فروشگاه اینترنتی است. فروشنده با شماره وارد می‌شود، در چت فروشگاه سایت را سفارش می‌دهد، در استودیو محتوا می‌سازد، از صندوق به مشتری جواب می‌دهد، و فروش و کیف را از پنل می‌بیند.

جملهٔ محصول: **بگو، بساز، بفروش.**

برند: علامت خورشید و ماه مسی روی پلاک زغالی. UI پنل فارسی و RTL است.

| نقش | نشانی |
| --- | --- |
| معرفی | https://sozan-core.ir |
| پنل | https://app.sozan-core.ir |
| API | https://api.sozan-core.ir |
| فروشگاه | `https://{slug}.sozan-core.ir` بعد از ساخت |
| گیت | https://github.com/Erfuni/sozan |

بازدیدکننده HTTPS می‌گیرد. لبهٔ ابرآروان با سرور اصلی **HTTP** حرف می‌زند.

`www.sozan-core.ir` با ۳۰۱ به ریشه می‌رود. ریشه لندینگ است؛ پنل فقط روی `app`.

## پشتهٔ قفل‌شده

خارج از این فهرست چارچوب جدید اضافه نشود.

**بک‌اند:** FastAPI، SQLAlchemy Async + asyncpg، PostgreSQL 16، Redis 7، Pydantic Settings، PyJWT، httpx، Pillow.

**فرانت:** Next.js 15 (App Router) + React 19، TypeScript، Tailwind CSS، shadcn/ui (دکمه، اینپوت، کارت، سلکت، تکست‌اریا). تصویر Next بدون بهینه‌ساز (`images.unoptimized`).

**قرارداد امنیتی بک‌اند**

- ورود با OTP؛ کد در Redis با TTL
- نشست با JWT (`HS256`)
- بررسی دسترسی روی هر اندپوینت محافظت‌شده
- رازها فقط در `.env` با مجوز محدود؛ هرگز در گیت

## معماری تمیز

```
مسیر HTTP (api/)
    → سرویس (services/)
        → مخزن (repositories/) → Postgres
        → state_store → فایل JSON هر مستأجر
        → redis_client → OTP، نرخ، state اوآث
```

1. مسیر فقط اعتبارسنجی، وابستگی و تبدیل خطاست. به دیتابیس دست نمی‌زند.
2. منطق فقط در `services/` است.
3. تنها `repositories/` به SQLAlchemy دسترسی دارد.
4. دامنهٔ فروشنده روی دیسک است، جدا از جدول‌های Postgres.
5. فرانت فقط از API حرف می‌زند (`frontend/lib/api.ts`). میان‌افزار Next برای auth نیست؛ گیت سمت کلاینت است (`OnboardGate`).

## چندمستأجری

شماره با `phone.normalize_phone` به `09XXXXXXXXX` تبدیل می‌شود: رقم فارسی/عربی، حذف غیررقم، `98…` دوازده‌رقمی و `9` ده‌رقمی به `0` می‌رسند.

`get_current_user` بعد از JWT، `set_tenant(user.phone)` می‌زند. حلقه‌های پس‌زمینه با `tenant_scope(phone)` روی همهٔ مستأجرها می‌گردند.

## احراز هویت و مجوز

### پنل

1. `POST /auth/otp/send` کد ۶رقمی می‌سازد، در Redis می‌گذارد، در تولید SMS می‌فرستد.
2. اگر `OTP_DEV=true` یا `mockSms` روشن باشد، `dev_code` در JSON برمی‌گردد.
3. `POST /auth/otp/verify` کاربر Postgres می‌سازد یا پیدا می‌کند و JWT می‌دهد.
4. فرانت توکن را در `localStorage` با کلید `sozan_token` می‌گذارد.
5. JWT: `sub` (UUID)، `role`، `permissions`، `iat`، `exp` — الگوریتم HS256، عمر پیش‌فرض ۷۲۰ دقیقه.

نقش پیش‌فرض همهٔ کاربران `admin` است با مجوزهای `campaigns:read`، `campaigns:write`، `campaigns:export`. سلسله‌مراتب نقش جدا نیست. **مدیر هاب** فقط وقتی است که شماره با `ADMIN_PHONE` یکی باشد (`isAdmin` در `/auth/me` و مسیرهای برداشت).

### مشتری فروشگاه

`POST /p/otp/send` و `/p/otp/verify`. کلید Redis جداست. خروجی توکن HMAC سی‌روزه با `role: shopper` است، نه JWT پنل. کاربر Postgres ساخته نمی‌شود.

### وب‌هوک و امضا

| مسیر | اعتبار |
| --- | --- |
| `POST /p/shop/paid` | هدر `X-Sozan-Sign` = HMAC-SHA256 بدنه با `JWT_SECRET` |
| `POST /channels/sendbox/webhook` | `?token=` HMAC کلید `sendbox-webhook` |
| `POST /channels/unipile/webhook` | `?token=` یا هدر `Unipile-Auth` |
| `POST /channels/unipile/notify` | `?token=` به‌علاوهٔ `tenant` |
| `GET /public-media/{token}` | توکن امضاشدهٔ کوتاه‌عمر |

## اجرای محلی

از ریشهٔ مخزن:

```bash
cp .env.example .env
# JWT_SECRET را عوض کن. OTP_DEV=true بماند تا کد ورود در پاسخ بیاید.

docker compose up -d
# Postgres :5432  Redis :6379

cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

cd ../frontend
npm install
npm run dev
# پنل :3000 — API پیش‌فرض http://127.0.0.1:8000
```

روی `localhost` مسیر `/` همیشه لندینگ است؛ پنل از `/login` باز می‌شود. شکاف لندینگ/پنل فقط با هاست واقعی `app.sozan-core.ir` دیده می‌شود.

## معماری استقرار

پنل، API، Postgres، Redis و پراکسی فروشگاه‌ها روی **هاب** هستند. گیت‌وی OpenClaw و وزن مدل روی **ماشین خانه** می‌مانند.

```
بازدیدکننده --HTTPS--> ابرآروان --HTTP :8088--> nginx هاب
                              |-> پنل 127.0.0.1:3010
                              |-> API 127.0.0.1:8012
                              '-> فروشگاه 127.0.0.1:{port}

API هاب --18789--> گیت‌وی سوزان روی 94.183.65.149
اینستاگرام/تلگرام از SOCKS خانه 127.0.0.1:10888
npm فروشگاه از HTTP پروکسی خانه 127.0.0.1:10889
یونى‌پایل از SOCKS 127.0.0.1:10890 (Tailscale)
مدل از تونل معکوس SSH روی 127.0.0.1:9292
```

- IP عمومی هاب برای مبدأ CDN: `37.152.189.216`
- IP خانه برای گیت‌وی: `94.183.65.149`
- origin بین لبه و هاب HTTP است؛ TLS مال لبه است.

پیام‌رسان‌ها از اینترنت مستقیم هاب فیلتر می‌شوند؛ ترافیک کانال از تونل خانه می‌رود.

## DNS و دامنه

زون `sozan-core.ir` در ابرآروان. رکورد A ابری با `upstream_https=http` برای `@`، `www`، `app`، `api` و بعد از ساخت برای `{slug}`. ویلدکارد `*` از API ابرآروان برای این زون ساخته نشد.

دامنهٔ مشتری: پنل CNAME به `{slug}.sozan-core.ir.` نشان می‌دهد. سوزان DNS رجیسترار را عوض نمی‌کند. بعد از ذخیره، lookup و CNAME Setup ابرآروان برای SSL لبه. nginx Host سفارشی را از `deploy/shop-custom-names.conf` به همان پورت می‌فرستد.

لیبل DNS فارسی نمی‌شود. کلید ابرآروان فقط در env هاب با mode `600`.

## نقشهٔ API

سلامتی: `GET /health` → `{ok: true}`. ریشه به ورود پنل ریدایرکت می‌شود.

مجوز: **عمومی**، **JWT**، **R/W/E** = JWT + `campaigns:read|write|export`، **ادمین هاب** = همان + `ADMIN_PHONE`، **وب‌هوک** = HMAC.

هدر تکرار: `Idempotency-Key` یا `X-Idempotency-Key` روی چت/بیلد فروشگاه، چت/انتشار/بازتولید استودیو، پاسخ صندوق.

### ریشه و ورود

| متد | مسیر | مجوز |
| --- | --- | --- |
| GET, HEAD | `/` | عمومی → ریدایرکت ورود |
| GET | `/health` | عمومی |
| POST | `/auth/otp/send` | عمومی `{phone}` |
| POST | `/auth/otp/verify` | عمومی `{phone, code}` → JWT |

## پیش‌نمایش زنده

`shop-live-build.tsx`: روی دسکتاپ iframe با مقیاس ۷۵٪ و کنارش `ShopEditor` (حالت طراحی با کلیک المان را انتخاب می‌کند؛ حالت مرور لینک را آزاد می‌گذارد؛ تب صفحه: خانه / کالاها / سبد). روی گوشی (`max-width: 1023px`) صفحه فقط خود سایت است در اندازهٔ واقعی گوشی و هیچ چتی ندارد: انگشت را روی هر بخش نگه می‌دارند (۴۸۰ میلی‌ثانیه، حرکت زیر ۱۰ پیکسل)، `/sozan-preview-beacon.js` همان بخش را (متن، یا عکس با `src`) با `longPress: true` به پنل می‌فرستد و `ShopEditSheet` از پایین باز می‌شود: دستور آزاد، متن تازه، «عکس از گوشی» (`POST /shop/image`) و برای عکس بالای سایت «با هوش مصنوعی بساز». زیر پیش‌نمایش دو دکمه است: «بیلد» (فعال وقتی `pendingBuild > 0`) و «برگشت» (فعال وقتی `shop.undoDepth > 0`؛ با هر بیلد موفق صفر می‌شود).

nginx فروشگاه قبل از `</body>` beacon را با `sub_filter` تزریق می‌کند؛ فایل روی هاب در `/var/lib/sozan-core/sozan-preview-beacon.js` است و `deploy/hub-install.sh` از `frontend/public/` کپی‌اش می‌کند (کش ۳۰ ثانیه). پیام‌های پنل به beacon: `apply`، `reset`، `undo` (با `to`)، `clear`.

پشتهٔ «برگشت» (`shop_undo_service.py`): هر ویرایش موفق یک عکس‌فوری از فایل‌های قابل‌ویرایش در `.sozan-undo/<n>/` و یک `<n>.json` (شمارندهٔ `pendingBuild` قبل از آن، فایل‌هایی که ساخت، عکس بالای سایت، قیمت‌ها، عکس‌های کالا) نگه می‌دارد؛ سقف ۱۲ مرحله؛ بیلد موفق پشته را پاک می‌کند.

صدای دستیار (`shop_voice_service.py`): مصاحبهٔ ساخت فروشگاه را مدل می‌گرداند (چند پرسش دربارهٔ کالا، مشتری، حس، رنگ و داستان؛ `brief` را پر می‌کند؛ ساخت فقط وقتی شروع می‌شود که فروشنده در همان پیام خواسته باشد و حس و رنگ معلوم باشد) و پاسخ نتیجهٔ ویرایش، ساخت و وضعیت را با جملهٔ خودش می‌گوید. پاسخی که نقل‌قول واقعیت را بیندازد، موفقیتِ نشده را ادعا کند، قول بدهد یا فارسی نباشد دور ریخته می‌شود و متن ساده می‌آید؛ اگر مدل جواب ندهد یا سقف بودجه پر باشد همان سناریوی ثابت قدیمی اجرا می‌شود.

## مدل زبانی و observe

`LOCAL_LLM_URL` پیش‌فرض `http://127.0.0.1:9292/v1` → observe خانه → llama-swap `127.0.0.1:19292`.

سطح‌ها: `shop`، `shop-edit`، `studio`، `inbox`، `voice`، `factory`، `image`.

پیش‌فرض: `factory` به ابر اگر `CLOUD_LLM_URL` و توکن باشد؛ استودیو `STUDIO_LLM_MODEL`؛ `voice`/`inbox` مدل محلی؛ بقیه `CHAT_LLM_MODEL`. مسیر observe هر ۳۰ ثانیه در `llm-routing.json` ذخیره می‌شود.

GPU1 یک مدل بزرگ را نگه می‌دارد. `LOCAL_LLM_MODEL` و `CHAT_LLM_MODEL` هر دو `qwen3.8-27b` باشند تا با `DESIGN_27B` کارخانه یکی باشد؛ مدل GPU1 متفاوت (مثل `ornith-1.5-35b`) باعث می‌شود چت و بیلد هم‌دیگر را بیرون بیندازند (خطای `extra GPU1 LLMs still loaded` و `llm_unreachable` در اسکن). گارد `factory_holds_gpu1` در `llm.py`: وقتی `site-builder/queue/fastpath/ACTIVE` با pid زنده یا `queue/phase.json` در فاز GPU1 و تازه‌تر از ۱۵ دقیقه باشد، هاب هیچ مدل GPU1 را unload نمی‌کند؛ اگر 27B لود است همان را می‌گیرد وگرنه به `qwen3.5-9b` می‌افتد و رویداد `gpu1-busy` می‌فرستد.

هدر درخواست مدل: `X-Sozan-Tenant`، `X-Sozan-Surface`، `X-Sozan-Brand`، `X-Sozan-Release`، `X-Sozan-Behavior`، `X-Sozan-Request`.

تصویر: مسیر `image` یا fallback `{observe}/observe/api/image`.

گیت‌وی: `GATEWAY_SOZAN_URL` مثلاً `http://94.183.65.149:18789`.

تکرارناپذیری ۲۴ ساعت در `idempotency.json`. محدوده‌ها: `shop-chat`، `shop-build`، `studio-chat`، `studio-publish`، `studio-regenerate`، `inbox-reply`.

## رسانه

چت (`chat_media_service`): سقف هر فایل ۱۵MB برای تصویر (png/jpg/webp/gif)، ویدیو (mp4/webm/mov) و صدا. نام `{uuid}-{kind}{ext}` زیر `chat-media/`. فایلی که در هیچ‌یک از `*.json` همان مستأجر نام برده نشده و از ۲۴ ساعت گذشته باشد پاک می‌شود (رسید، عکس تیکت، رسانهٔ دایرکت و چت فروشگاه نگه داشته می‌شوند).

رسانهٔ عمومی: `tenant|name|exp|hmac` با `JWT_SECRET`؛ حداقل TTL ۶۰ ثانیه.

## استقرار هاب

مسیر: `/home/ubuntu/sozan-core`.

| قطعه | نقش |
| --- | --- |
| `sozan-api.service` | uvicorn `127.0.0.1:8012` |
| `sozan-panel.service` | `next start` `127.0.0.1:3010` |
| `deploy/docker-compose.yml` | Postgres/Redis |
| nginx `sozan-core` | ۸۰ و ۸۰۸۸ |
| `sozan-unipile-socks.service` | SOCKS به نود Tailscale؛ در `hub-install.sh` نصب نمی‌شود |

نصب کامل: `bash deploy/hub-install.sh` — `.env` با mode ۶۰۰، کپی beacon، nginx، docker، venv با آینهٔ runflare، `npm run build` با `NEXT_PUBLIC_API_URL=https://api.sozan-core.ir`، systemd.

همگام‌سازی از ورک‌استیشن (`.env` و نقشهٔ فروشگاه و دادهٔ مستأجر را بازنویسی نکن):

```bash
rsync -avz --exclude-from=/home/demon/work-f/Sozan-Core/deploy/rsync-exclude \
  /home/demon/work-f/Sozan-Core/ \
  hub:/home/ubuntu/sozan-core/
```

بعد از فقط تغییر کد: `sudo systemctl restart sozan-api sozan-panel`. بعد از وابستگی یا nginx یا بار اول: `hub-install.sh`.

اشکال‌زدایی:

```bash
sudo journalctl -u sozan-api -f
sudo journalctl -u sozan-panel -f
# وضعیت مستأجر
ls /home/ubuntu/sozan-core/backend/data/tenants/
# نقشهٔ فروشگاه (روی هاب تولید می‌شود)
cat /home/ubuntu/sozan-core/deploy/shop-upstreams.map
```

`rsync-exclude`: venv، node_modules، `.next`، `.env*`، `backend/data/`، `.git`، `/campaigns/`، نقشه‌های nginx فروشگاه.

## متغیرهای محیط

نام‌ها در `.env.example`. مقدار واقعی در گیت نیست.

| گروه | کلید |
| --- | --- |
| هسته | `DATABASE_URL` `REDIS_URL` `JWT_SECRET` `JWT_EXPIRE_MINUTES` `ADMIN_PHONE` `CORS_ORIGINS` |
| OTP / پیامک | `OTP_TTL_SECONDS` `OTP_DEV` `SMS_PROVIDER` `SMS_IR_*` سهمیه و اضافه |
| پرداخت | `ZARINPAL_*` `PLAN_PRICE_*` `COMMISSION_BPS` |
| مدل | `LOCAL_LLM_*` `CHAT_LLM_MODEL` `STUDIO_LLM_MODEL` `CLOUD_LLM_*` `GATEWAY_SOZAN_URL` |
| دامنه | `ARVAN_*` `PANEL_URL` `PUBLIC_API_URL` |
| کانال | `TELEGRAM_BOT_TOKEN`+`TELEGRAM_CHAT_ID` (فقط بات هشدار مالک) `TELEGRAM_HUB_BOT_TOKEN` (بات مشترک فقط برای ارسال پست؛ برای دایرکت پول نمی‌شود) `INSTAGRAM_*` `SENDBOX_*` `UNIPILE_*` `CHANNEL_PROXY` `TRUSTED_IP_HEADER` |

## محدودیت‌ها

- لیبل DNS فارسی نمی‌شود.
- origin بین لبه و هاب HTTP است.
- گیت‌وی و وزن مدل روی خانه می‌مانند؛ قطع تونل ۹۲۹۲ چت مدل را می‌خواباند.
- OTP در حالت mock کد را در JSON می‌دهد. در پنجرهٔ `OTP_TEST_UNTIL` کد فقط برای شماره‌های ساختگیِ تست (و `OTP_TEST_PHONES`) برمی‌گردد؛ هرگز برای شمارهٔ واقعی یا مدیر هاب.
- ارسال خودکار واتساپ از صندوق deliver ندارد.
- پست استودیو تلگرام بدون بات ادمین و مقصد نمی‌رود.
- فروشگاه بدون بیلد تازه چک‌اوت قدیمی دارد.
- بله و روبیکا فقط اتصال توکن دارند.
- `/manage` فقط به انبار می‌رود.
