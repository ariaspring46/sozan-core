# ارزیابی هارنس چت فروشنده

تست کامل هارنس: مدل‌های واقعی، کد واقعی router، و فروشگاه آزمون جدا (`09128880001`). هر اثر بیرونی (پیامک، دایرکت، پوش، انتشار، کانتینر) جایگزین و شمرده می‌شود. هیچ تنانت تولیدی باز نمی‌شود.

## اجرا (روی هاب، با venv تولید، از کلونِ کامیتی که سنجیده می‌شود)

```bash
cd <clone>
python3 tools/harness_eval/selftest.py                       # آزمون‌های آفلاین امتیازدهی
/home/ubuntu/sozan-core/backend/.venv/bin/python tools/harness_eval/run.py cases --run-id B0 --dry
/home/ubuntu/sozan-core/backend/.venv/bin/python tools/harness_eval/run.py lock        # فقط بعد از تأیید مالک
/home/ubuntu/sozan-core/backend/.venv/bin/python tools/harness_eval/run.py cases --run-id B0
/home/ubuntu/sozan-core/backend/.venv/bin/python tools/harness_eval/run.py real-routes --run-id B0
python3 tools/harness_eval/report.py B0 [--baseline B1]
```

- `cases` بدون قفل اجرا نمی‌شود، مگر `--dev` (اجرای توسعه، قابل مقایسه نیست).
- هر مورد سه بار اجرا می‌شود. سقف خرج با `--budget` (پیش‌فرض ۰٫۴ دلار).
- رکوردها و گزارش‌ها در `~/sozan-eval/runs/<run-id>/` هستند و هرگز وارد git نمی‌شوند.
- مقایسه فقط بین دو اجرای غیر‌توسعه، هر کدام با سه تکرار و روی همان فایل قفل‌شده انجام می‌شود؛ در غیر این صورت گزارش «قابل مقایسه نیست» می‌دهد.

## فایل‌ها

| فایل | کار |
|---|---|
| `cases.json` | موردها: جمله، مسیر مورد انتظار، فایل‌های مجاز، ادعای پاسخ، وارسی‌ها |
| `cases.lock` | هش `cases.json` تأییدشده توسط مالک |
| `run.py` | اجرا: محیط سنجاق‌شده، جایگزین اثرهای بیرونی، ضبط نوبت‌ها، بازگردانی فیکسچر |
| `fixture.py` | فیکسچر طلایی: تنانت و پوشهٔ سایت، بازگردانی قبل از هر مورد |
| `score.py` | امتیازدهی خالص از روی شواهد؛ بدون وابستگی به اپ |
| `report.py` | گزارش فارسی، قاعدهٔ تصمیم در برابر پایه |
| `selftest.py` | جهش‌های عمدی: امتیازدهی باید هر خطای کاشته‌شده را بگیرد |
| `common.py` | مسیرها، هش فایل، فیلتر نویز چت |

## آنچه شمرده می‌شود

- **مسیر:** کارت، ابزار، آرگومان‌ها، سؤال یا پاسخ مستقیم.
- **فایل‌ها:** مجموعهٔ فایل‌های عوض‌شده باید برابر مجاز باشد؛ مقدار هر فایل با `select` و `equals` و `count_delta` وارسی می‌شود.
- **پاسخ:** ادعای موفقیت فقط وقتی درست است که وارسی‌های فایل درست باشند؛ عدد موجود در پاسخ؛ قالب و زبان.
- **وارسی:** `verify.ok` باید با شواهد فایل توافق داشته باشد.
- **ایمنی:** هیچ نوشتنی بی‌کارت، هیچ پیام بیرونی، هیچ ساخت یا کانتینر ناخواسته، پاسخ بی‌خطا، و ماندن در فیکسچر.

## وضعیت

- **فهرست موردها:** نسخهٔ ۲ (`cases.json`، ۴۷ مورد، قفل در `cases.lock`). نسخهٔ ۱ برای مقایسه نگه داشته شده (`cases.v1.*`). مقایسه فقط بین دو اجرا روی همان نسخه معتبر است؛ تغییر یک مورد یعنی نسخهٔ تازه و پایهٔ تازه.
- **پایه:** B2 روی نسخهٔ ۲: ۱۲۵ از ۱۲۹ (۹۶٫۹٪)، نوسان ۴٫۷٪. نوبت‌های واقعی: تصمیم‌گیر ۶۷٫۶٪.
- **تصمیم‌گیر:** `perplexity/pplx-decider-v1.2` (`DECIDER_MODEL` در `.env` تولید). مدل‌های «Decisions» در فهرست ساده نیستند؛ با `GET /api/v1/models?output_modalities=decisions` دیده می‌شوند.
- **سنجش مسیر واقعی با کنش تازه:** `decider_eval.py collect --models perplexity/pplx-decider-v1.2 --formats object --tag <نام>` پاسخ‌های خام را در `runs/calib-<نام>/raw.jsonl` می‌گذارد. ردیف‌های ۴۲۹ را پیش از امتیازدهی حذف و دوباره جمع کنید (`CONCURRENCY` کم است).
- **پاک‌سازی:** ردیف‌های خام و نوبت‌های واقعی فقط روی هاب می‌مانند و وارد git نمی‌شوند.

## شناخته‌شده و هنوز انجام‌نشده

- **ساخت واقعی فیکسچر انجام نشده.** `R14`، `R15`، `B01` و `B02` (لایهٔ ساخت و سایت زنده) `needs_build` هستند و اجرا نمی‌شوند.
- **سه مورد ناپایدار به‌خاطر کلمهٔ پاسخ، نه خطای محصول:** `R03` (عدد با حروف، «سه‌تا»)، `E04` (طبقه‌بندی «تو کادر آماده‌ست» به‌عنوان ادعا)، `R21` (فهرست کلمه‌های پذیرفته). اصلاحشان نسخهٔ ۳ می‌خواهد.
- **۴۲۹ تصمیم‌گیر:** خطای محدودیت سرعت سرویس‌دهنده گاهی موردی را «تصمیم‌گیر پاسخ نداد» می‌کند؛ مورد را تنها دوباره اجرا کنید (`--dev --only ID`) پیش از حکم.
- **نگاشت برچسب‌های واقعی** به نام ابزار تقریبی است (`tool.startswith(label)`).
- **اثرهای بیرونی جایگزین‌شده:** `inbox.reply`، `sendbox.send_message`، `sms.send_otp`، `seller_alerts` (push، پیامک، alert، alert_soon)، `studio.publish`. کانال‌های دیگر (واتساپ، بله، روبیکا، پیامک سفارش ملی‌پیامک، تلگرام) هنوز جایگزین نشده‌اند.
- **هزینهٔ مدل صوتی** در بودجه شمرده می‌شود اما ثبت نمی‌شود.
- **اجرای واقعی کانتینر** (ساخت) نیاز دارد که `subprocess.run` برای موردهای `build` آزاد شود؛ فعلاً همه بلاک‌اند.
